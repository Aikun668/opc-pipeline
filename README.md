# OPC Pipeline基于 OpenClaw 的 24h 自动化编码/审查/测试/交付系统。## 工作流```Planning → Coding → Pre-filter → Deep Review → Testing → Delivery(Claude)      (GLM)       (DS-chat)       (DS-R1)           (Kimi)       (Claude)```## 架构```┌──────────────────────────────────────────────┐│               Orchestrator                    ││  StateMachine │ CircuitBreaker │ LLMManager  │└──────────────────────┬───────────────────────┘                       │              ┌────────▼────────┐              │   Supervisor    │  守护进程，自动重启              └────────┬────────┘         ┌─────────────┼─────────────┐      Coder        Reviewer       Tester      Actor         Actor         Actor         └───── TaskWatcher (poll+watch) ─────┘                       │              ┌────────▼────────┐              │  Spawn Workers  │  spawn-adapter.js              │  api/mock/cli   │              └─────────────────┘```## 快速开始```bashnpm install \\\\\\\\\\\\\\\&\\\\\\\\\\\\\\\& cp .env.example .env   # 安装 + 配置 API Keynode test-fixes.js                     # 运行测试node supervisor.js                     # 拉起全部 Actornode orchestrator.js                   # 运行任务（默认 mock 模式）```|模式|说明||-|-||`OPC\\\\\\\\\\\\\\\_SPAWN\\\\\\\\\\\\\\\_MODE=mock`|本地测试，不消耗 API（默认）||`OPC\\\\\\\\\\\\\\\_SPAWN\\\\\\\\\\\\\\\_MODE=api`|生产模式，直连 LLM API||`OPC\\\\\\\\\\\\\\\_SPAWN\\\\\\\\\\\\\\\_MODE=cli`|调用 openclaw CLI|## 模块一览|模块|文件|职责||-|-|-||Orchestrator|`orchestrator.js`|6 阶段调度、崩溃恢复、Diff 生成、Delivery 打回||StateMachine|`state-machine.js`|阶段定义与转换逻辑，超时/重试配置||LLMManager|`llm-manager.js`|多模型调度，熔断集成，Token 统计||SpawnAdapter|`spawn-adapter.js`|api/mock/cli 三模式适配||Supervisor|`supervisor.js`|Actor 守护，指数退避重启（1s→30s）||TaskWatcher|`pipe/task-watcher.js`|轮询+fs.watch 混合监听，WSL 兼容||PipeManager|`pipe/pipe-manager.js`|管道通信，信标管理，ENOENT 防御||CircuitBreaker|`circuit-breaker.js`|熔断保护（closed→open→half\_open）||MemoryManager|`memory/memory-manager.js`|对话归档、摘要生成、语义检索||Monitor|`monitor.js`|实时面板：任务/熔断/Token/性能||Prompts|`prompts/templates.js`|6 阶段标准化 Prompt，强制 JSON 输出|### LLM Clients|客户端|模型|用途||-|-|-||`claude-client.js`|Claude Sonnet 4.6|Planning + Delivery||`glm-client.js`|GLM-5.1|Coding||`deepseek-client.js`|DS-chat / DS-R1|Pre-filter / Deep Review||`kimi-client.js`|moonshot-v1-32k|Testing|## 目录结构```opc-pipeline/├── orchestrator.js          # 主控调度器├── supervisor.js            # Actor 守护进程├── spawn-adapter.js         # spawn 适配层├── state-machine.js         # 状态机├── circuit-breaker.js       # 熔断器├── llm-manager.js           # 多模型调度├── monitor.js               # 监控面板├── prompts/templates.js     # Prompt 模板├── llm-clients/             # LLM 客户端实现├── actors/                  # Actor（coder/reviewer/tester）├── pipe/                    # 管道通信 + TaskWatcher├── memory/                  # 记忆管理 + 角色配置 + 归档├── config/models.json       # 模型 \\\\\\\\\\\\\\\& API Key 配置├── state/                   # 任务状态持久化└── var/                     # 运行时（pipe/escalations/）```## 配置* **模型配置**：`config/models.json` — 各阶段 provider/model/temperature/timeout* **环境变量**：`.env` — CLAUDE\_API\_KEY / GLM\_API\_KEY / DEEPSEEK\_API\_KEY / KIMI\_API\_KEY / OPC\_SPAWN\_MODE* **角色配置**：`memory/roles/` — coder-profile.md / reviewer-profile.md / tester-profile.md## 测试```bashnode test-fixes.js                           # 单元测试（12 项）OPC\\\\\\\\\\\\\\\_SPAWN\\\\\\\\\\\\\\\_MODE=api node smoke-test-api.js    # API 冒烟测试（6 阶段连通性）```## 故障排查|症状|排查||-|-||任务卡住|`node monitor.js` → 查熔断器 → 检查 Actor 进程 → `ls var/pipe/`||Actor 崩溃|`node supervisor.js` 自动重启；连续崩溃 10 次查 Actor 脚本||WSL 监听丢事件|已由 TaskWatcher 修复；可缩短 pollInterval||重启后任务丢失|`resumePendingTasks()` 自动恢复；查 `state/` 目录||熔断器频繁打开|查 `var/escalations/`；调 `config/models.json` 阈值|## Changelog|版本|日期|要点||-|-|-||v2.2|2026-04-14|6 阶段 LLM API 直连；api/mock/cli 三模式；Delivery 打回；Token 追踪；真实 Diff；冒烟测试||v2.1|2026-04-13|Supervisor 守护；TaskWatcher WSL 修复；spawn 适配层；崩溃恢复||v2.0|2026-04-13|5 阶段状态机；记忆管理；熔断器；输出硬化；监控面板||v1.0|2026-04-10|初始版本，基础管道 + 静态角色|MIT
