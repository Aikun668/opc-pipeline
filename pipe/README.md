# OPC Pipeline - 管道目录规范# # 目录结构：/tmp/opc-pipe/{taskId}/# 所有 Agent 间通信必须通过落盘文件，禁止 Prompt 直接传递大段内容## 目录权限* 主控 (Orchestrator): 读写所有目录* Coder Actor: 只读写自己的任务目录* Reviewer Actor: 只读写自己的任务目录* Tester Actor: 只读写自己的任务目录* Spawn Worker: 只写，写完立即退出## 文件命名规范### 输入文件（主控写入，Actor读取）* `input.json` - 任务指令（必须存在）* `context.json` - 额外上下文（可选）### 输出文件（Actor/Worker写入，主控读取）* `output.json` - 执行结果（必须存在，严格<500字符）* `code.patch` - 代码变更（可选，大文件）* `test-report.json` - 测试报告（可选）* `review-report.md` - 审查报告（可选）* `log.txt` - 执行日志（可选，用于调试）### 状态文件（运行时更新）* `.lock` - 目录锁（防止并发写入）* `.heartbeat` - 心跳时间戳（Actor存活检测）* `.pid` - 占用进程ID## 输出JSON强制格式```json{  "version": "1.0",  "status": "success|fail|error",  "stage": "coding|testing|reviewing",  "summary": "一句话结果，必须<100字",  "artifacts": {    "patch": "/tmp/opc-pipe/TASK-001/code.patch",    "test": "/tmp/opc-pipe/TASK-001/test-report.json"  },  "metrics": {    "linesChanged": 50,    "filesModified": 3,    "testCoverage": 85  },  "nextAction": "request\\\\\\\_review|request\\\\\\\_test|request\\\\\\\_fix|complete",  "error": null}```## 约束检查清单* \[ ] output.json 总字符数 <= 500（去除空白后）* \[ ] 必须包含 version, status, summary, nextAction* \[ ] summary 长度 <= 100 字* \[ ] 大文件必须通过 artifacts 引用，不得内嵌* \[ ] 状态转换必须符合状态机：pending → coding → testing → reviewing → done## 错误处理* 违反格式约束 → 主控丢弃输出，标记任务失败* 文件锁超时(30s) → 强制释放锁，记录警告* 心跳超时(5min) → 标记 Actor 为僵尸，重启## 清理策略* 完成任务后保留 24 小时（用于审计）* 超期自动清理（Cron 每日执行）* 失败任务保留 7 天（用于分析）
